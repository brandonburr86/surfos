unzip - list, test and unpack zip archives

SYNOPSIS
    unzip [-l|-t|-p] [-o|-n] [-q] [-d dir] file.zip [name...]

DESCRIPTION
    Unpacks a zip into the current folder, or into dir, which is made
    if need be. Options may come after the file's name. The names are
    patterns that choose the members, with * and ?; * goes across a /,
    and case does not matter.

    Stored and deflated members are taken, and each one's CRC and
    sizes are checked. Without -o or -n, a file that exists stays and
    the status is 2. Names are read as UTF-8 or code page 437, whichever
    the archive means, and written as UTF-8. Times and modes are not
    kept: SurfOS cannot set them.

    unzip refuses a name that is absolute or holds .., and one with a
    control character or a character FAT does not allow
    (: * ? " < > | \), or that ends in a space or a dot. Encrypted
    members, other methods, links and devices are skipped. Each of
    those is said and the status is then 2; the
    members around it are still taken. A member that holds more or
    less than it claims is deleted. An archive whose members overlap,
    or claim more than the file holds, is refused whole: that is how a
    zip bomb is made. So is a central directory over 16 MB, and Zip64,
    which is only for what FAT could not hold.

    A member that would land on the archive itself is skipped. A file
    that cannot be finished is deleted, or the old one stays. Being
    killed part way, by Ctrl+C or otherwise, is the exception: nothing
    can then tidy up, so a new file may stay short, and nothing marks
    it. A later unzip -n sees that the file exists, keeps it, and gives
    status 0: after a kill use -o, which makes each file whole again.

    A zip is read from its end, so it cannot come through a pipe. Past
    2 GB SurfOS can only read forward, so a large archive works, but
    each member past 2 GB costs a read of what comes before it. If an
    archive would send unzip back and forth past 2 GB, it stops after
    reading four times the file, and says so: name the members you
    want.

    The status is 0, or 2 if anything was skipped or went wrong.

OPTIONS
    -l      List the members: size, date, name. Nothing is written.
    -t      Check each member. Nothing is written.
    -p      Write the members' data to standard output.
    -o      Replace files that exist, each only once the new one is
            whole.
    -n      Leave files that exist, quietly.
    -q      Say only what went wrong.
    -d dir  Unpack into dir.

EXAMPLES
    unzip -l /usb0p1/PHOTOS.ZIP
    unzip /usb0p1/SITE.ZIP -d /hda1/SITE
    unzip -p /usb0p1/SITE.ZIP readme.txt | less
