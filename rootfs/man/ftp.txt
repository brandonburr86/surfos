ftp - files to and from an FTP server

SYNOPSIS
    ftp [-n] [host [port]]

DESCRIPTION
    Copies files to and from a server, at a prompt or from a script
    on standard input. With a host it connects, on port 21 unless
    another is given, and logs in as anonymous.

    Transfers are binary until ascii says otherwise. Every data
    connection is passive (EPSV, then PASV) and goes only to the
    address the session reached, whatever the server names, and to a
    port from 1024. Commands and data are not encrypted: a password
    crosses the network as it is.

    Everything a server says is treated as hostile. Its text is shown
    with control characters and escape sequences as ?, and a file
    counts only when the server has said it is whole and, in binary
    mode, as many bytes came as it promised.

OPTIONS
    -n    Do not log in by itself: user does it.

COMMANDS
    open host [port]      connect; a session open ends first
    user name             log in; the password is asked for
    ls [path]             the names in a folder
    dir [path]            a folder, in full
    cd path               change the server's folder
    pwd                   the server's folder
    get remote [local]    fetch a file; - for standard output
    put local [remote]    send a file
    mget pattern...       fetch what the patterns match
    mput pattern...       send the local files they match
    reget remote [local]  go on with a file cut short
    lcd [folder]          the local folder
    delete name           delete a file on the server
    mkdir name            make a folder on the server
    rmdir name            remove a folder on the server
    rename from to        rename on the server
    size name             a file's size on the server
    binary                the bytes as they are (the default)
    ascii                 text: line ends converted
    status                how things stand
    help [command]        the list of commands
    quit                  leave; so does the end of the input

    A name with blanks goes in double quotes. Lines starting with #
    are comments. Patterns take * ? and [a-z].

PASSWORDS
    A password is asked for without echo, on the terminal itself,
    also when the commands come from a script: it is never read from
    a line, a script or the command line, and without a terminal the
    login fails. It is never shown or kept, and is hidden if the
    server says it back. Anonymous never asks.

FILES
    get replaces a file through a new file beside it, renamed over
    the old one when all is well; until then the old file stays as it
    was. A new file is deleted again if the transfer fails.

    reget adds to a file from its end, and keeps what came when it
    fails, so the next reget goes on: start with reget, not get, on a
    connection that may break. It needs binary mode, and a server
    that sends more than was left has what it added cut off again.

    mget lists the folder and matches the names here, so a name that
    does not match is not taken, whatever the server lists. Only the
    last part of a listed name counts, and it must be safe as a file
    here: no .. and no / , nothing FAT refuses, no - at its start and
    no dot or blank at its end. Others are left out and said. mget
    never replaces a file unasked: at a terminal it asks, in a script
    it leaves the file and says so. * and ? do not match a leading
    dot.

    A file on SurfOS holds less than 4 GB. File times are not kept.

CTRL+C
    Ctrl+C stops the command that runs: a transfer is aborted and
    its file cleaned up, and the prompt comes back. Stopping any other
    command closes the connection. A script ends, with status 130. At
    the prompt Ctrl+C leaves ftp, as it leaves any program. A kill
    leaves a partial file, or a .tmp, where it was.

    Status 0 when every command worked, 1 when the server said no to
    one or mget left something out, 2 for anything worse.

EXAMPLES
    ftp 10.0.0.4
    printf 'cd pub\nmget *.txt\n' | ftp ftp.example.com
    ftp -n 10.0.0.4 2121
