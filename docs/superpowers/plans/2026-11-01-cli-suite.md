# Brief: the command-line suite

## The request

The owner, 2026-11-01: build all the command-line tools from that day's list of what SurfOS lacks, in parallel.
SurfOS runs itself well but has few tools for making things: no archives, no `diff`, no `sed` or `awk`, no check of a
disk, no manual. This brief adds them.

**In scope:** `sed`, `awk`, `diff`, `patch`, `cmp`, `tar`, `gzip`, `gunzip`, `zcat`, `unzip`, `fsck`, `top`, `man`,
`telnet`, `ftp`, `basename`, `dirname`, `od`, `base64`, `strings`, `file`, `paste`, `join`, `comm`, `fold`, `nl`, `rev`,
`cal`, `tree`, `watch`, `bc`; `grep -E`; and what they need in libsurf: a regular expression library, `strtod`, `math.h`,
`getopt`, `system`, `popen`.

**Out of scope:** `cc`, `make`, `ssh`, a terminal multiplexer, mail, `ntp`, `dig`, `traceroute`, anything on the desktop,
and SurfCPU (riscv32 has no user mode; a shared kernel change must still pass its check, below).

## The manual

Every tool gets `rootfs/man/<name>.txt`, plain UTF-8, at most 72 columns, in this shape:

```
sed - a stream editor for filtering and changing text

SYNOPSIS
    sed [-n] [-E] [-i] [-e script] [-f file] [script] [file...]

DESCRIPTION
    What it does, in plain sentences, and what SurfOS does differently
    from other systems.

OPTIONS
    -n    Print only what p asks for.

EXAMPLES
    sed -n '/error/p' /hda1/LOG.TXT

SEE ALSO
    grep, awk
```

The first line is the name, ` - `, and one line of description: `man -k` searches those lines. Sections with nothing to
say are left out. Say what the tool cannot do here (no file times set, no permissions) where someone would trip on it.

## Rules for every tool

**Style.** The surrounding code's: the header block with the date 11/01/26, `if(x)`, four spaces, comments in plain
sentences that say why. Read `user/bin/grep.c`, `user/bin/lineutil.h` and `user/bin/fileutil.h` first, and use them. A
tool's options are described in its header comment. Original code only: no new third-party source and no new licence.

**Testable.** Keep the logic apart from the system calls in a file `tests/host/` can compile, as `user/wclock/clock.c`
and `user/telnetd/telnet.c` are. Where a real tool exists, compare against it on a corpus in the host test (GNU tools in
the Docker image, BSD ones on the Mac; skip a comparison, saying so, when that tool is not installed). A tool that reads
files or a network gets malformed, truncated and oversized input in its tests too, under `-fsanitize=address,undefined`
where the host compiler has it.

**Behaviour.**

- Status 0 for success, 1 for a negative answer (as `grep` and `diff`), 2 for trouble. Messages on stderr as
  `tool: what: why`. `-` is standard input where a file is expected. A tool in a pipeline ends cleanly when its reader goes.
- Where a tool counts characters, a character is a UTF-8 sequence, as in `cut -c`; invalid bytes count one each and pass
  through unchanged. Otherwise work in bytes. Never split a sequence.
- Stream wherever the format allows. A file on a stick can be nearly 4 GB and `make test` gives the machine 256 MB, so
  never load a whole input without need, check every allocation, and fail with a message rather than a crash.
- No recursion that input can drive without a limit: the user stack stops at 4 MB. A kernel stack is far smaller.
- A program has 16 descriptors (`NR_OPEN`): read a directory whole and close it before going into it, as `fileutil.h` does.
- SurfOS has no `fork`, `exec`, `mmap`, symbolic links, permissions, owners, or a way to set a file's time. Programs start
  programs with `spawnx()` and pipes. FAT names ignore case and refuse `: * ? " < > | \`. `lseek` takes 32 signed bits and
  sizes are `unsigned`: take care past 2 GB.
- **Replacing a file:** `user/bin/saveutil.h`, always (`su_begin`, `su_commit`, `su_abort`, `su_say`). It writes beside the
  file and renames, as `edit` does, and handles FAT's half-done renames. A file that did not exist is made with
  `O_CREAT | O_EXCL`, and deleted again if the tool fails partway. Never truncate a file the user already had.
- **Untrusted input:** anything from a file or the network. Bound every length, check every offset, and take no path from
  an archive or a server without refusing absolute paths and `..`.

## The tracks in detail

### text, stage 1: the libsurf additions

Commit this first, report, and stop: lang is waiting on it.

- **`regex.h`:** POSIX `regcomp`, `regexec`, `regerror`, `regfree`, with `REG_EXTENDED`, `REG_ICASE`, `REG_NOSUB`,
  `REG_NEWLINE`, `REG_NOTBOL`, `REG_NOTEOL`, `regmatch_t`. Basic and extended syntax, bracket expressions with
  `[:classes:]`, intervals, and back-references in basic syntax. Leftmost-longest, as POSIX says. `.` and a bracket take a
  whole UTF-8 sequence. No catastrophic cases: time bounded by pattern times input where there are no back-references, and
  a step limit that fails with an error where there are. Compiled size and nesting bounded.
- **`stdlib.h`:** `strtod` and `atof`, correctly rounded, with `inf` and `nan`; `system()` through `/initrd/bin/surfsh -c`.
  **`stdio.h`:** `popen`, `pclose` likewise, with `spawnx` and a pipe; `sscanf`'s `%f %g %e`.
  **`unistd.h`:** `getopt`, `optarg`, `optind`, `opterr`, `optopt`.
- **`math.h`:** `sin cos tan asin acos atan atan2 sinh cosh tanh exp log log2 log10 pow sqrt cbrt hypot floor ceil round
  trunc fabs fmod modf frexp ldexp`, with `isnan isinf isfinite`, `HUGE_VAL INFINITY NAN M_PI M_E`. Portable C: no inline
  assembly, so programs can one day run on SurfCPU. Within 2 ulp of the host's libm across a test grid, and exact for the
  special cases C names.

`test_regex`, `test_strtod`, `test_libm`, `test_getopt` go in `make unittest`, cross-checked against the host's libc.

### text, stage 2: grep -E and sed

- **`grep`:** moves onto the library and gains `-E`. Its existing behaviour and smoke steps stay.
- **`sed`:** `-n -e -f -E -r -i[suffix] -s`; addresses `n $ /re/ \cREc first~step addr,+n addr,~n 0,/re/` and `!`;
  commands `{} = a b c d D g G h H i l n N p P q Q r s t T w x y : #`; `s` flags `g p N I w`, with `&` and `\1`-`\9`. `-i`
  goes through saveutil. Compare with GNU and BSD `sed` on a corpus.

### lang: bc, then awk

- **`bc`:** POSIX `bc`: arbitrary precision, `scale ibase obase`, variables, arrays, functions, `auto`, `if while for`,
  `-l` with its library. Bounded by memory, with a clear message at the limit.
- **`awk`:** POSIX `awk`: patterns, ranges, `BEGIN`, `END`, fields, `NF NR FNR FS OFS ORS RS RSTART RLENGTH SUBSEP ENVIRON
  ARGC ARGV CONVFMT OFMT`, associative arrays with `delete`, `in` and `SUBSEP`, functions with recursion, all forms of
  `getline`, `print` and `printf` to `>`, `>>` and `|`, `close`, `fflush`, `system`, `length substr index split sub gsub match
  sprintf tolower toupper`, `sin cos atan2 exp log sqrt int rand srand`, `-F -v -f`, `nextfile`. `length`, `substr` and
  `index` count characters. Compare with the Mac's `awk` (the one true awk) and with `gawk`/`mawk` where installed.

Start with `bc`. When told that text's stage 1 is committed, merge that commit into `cli/lang` and go on to `awk`.

### diff: diff, patch, cmp and the small utilities

- **`diff`:** an O(ND) algorithm that does not need quadratic memory. Normal, `-u [n]`, `-c`, `-q`, `-r`, `-i`, `-b`, `-w`,
  `-B`; "Binary files differ". Status 0, 1, 2.
- **`patch`:** unified, context and normal diffs; `-p -R -i -o -d -N -f --dry-run`; offset and fuzz; `.rej` files; files
  made and removed through `/dev/null`. Refuses absolute paths and `..`. Writes through saveutil. A property test: for
  generated pairs, `diff` then `patch` gives the second file back, forward and with `-R`.
- **`cmp`:** `-l -s -n`. **`comm`:** `-123`. **`join`:** `-t -1 -2 -a -v -o`. **`paste`:** `-d -s`. **`fold`:** `-w -s -b`.
  **`nl`:** `-b -w -s -v -i`. **`rev`**, **`basename`** (with a suffix), **`dirname`**. **`od`:** `-A -t -c -x -b -N -j`.
  **`base64`:** `-d -w`, streaming. **`strings`:** `-n`. **`file`:** by content, not name: ELF, BMP, PNG, JPEG, GIF, gzip,
  zip, tar, PDF, a FAT image, a script, ASCII or UTF-8 text with its line ends, empty, a directory. **`tree`:** `-a -d -L -s`.
  **`cal`:** `[[month] year]`, weeks from Sunday, as `user/wclock/clock.c`'s month prints.

### archive: gzip, tar, unzip

- **`inflate` and `deflate`** in libsurf, streaming, with `crc32`. `web/m2` has a reviewed inflate in
  `user/wundertow/image_png.c` (`git show web/m2:user/wundertow/image_png.c`); you may start from it, and say so in your
  account. Leave `user/wundertow/` alone. Deflate does LZ77 with hash chains and dynamic Huffman blocks.
- **`gzip`, `gunzip`, `zcat`:** `-c -d -f -k -t -1..-9`. Several members, the header's flags, CRC and length checked,
  trailing garbage refused. The input goes only when the output is safely written and synced. Verified both ways against
  the host's `gzip`.
- **`tar`:** `c x t` with `z v f - C`, `--exclude`. Writes ustar. Reads ustar, GNU long names and pax `path` and `size`
  records, so archives from the Mac and Linux work. `f -` is a pipe. Refuses absolute paths and `..`. Links, devices and
  anything else FAT cannot hold are skipped with a message, and the status says so. File times cannot be set. Replacing a file
  goes through saveutil.
- **`unzip`:** `-l -t -d -o -n -q -p`. Stored and deflated, CRC checked, UTF-8 and code page 437 names. Reads the central
  directory, and bounds it. Refuses encrypted entries, absolute paths and `..`. Bounded against archives that claim one size
  and hold another.

### fsck

`fsck [-v] <dev>` checks a FAT12, FAT16 or FAT32 volume without writing. `fsck -r <dev>` repairs it. It is a kernel command
because programs cannot read raw disks: `fs/fat_check.c` is pure, with its reads and writes through a small interface, so
`tests/host/test_fsck.c` runs it over images, as `fs/fat_mkfs.c` is run.

- **What it checks:** the boot sector and BPB, the backup, FSInfo, that the FATs agree, the reserved entries, the clean bit;
  from the root, every directory's entries, `.` and `..`, long name sets (order, checksum), names; each chain: out of range,
  free or bad clusters, loops, and length against size. Two entries on one chain (the pair that `saveutil.h`, `edit` and
  the desktop guard against). Clusters in use that nothing reaches. The free count.
- **Read-only runs:** on an unmounted or read-only volume. A volume mounted read-write is refused, with the reason.
- **`-r`:** goes through `bdev_may_format()`, the one rule for what may be changed, shows what it will change, and asks for
  the device's name through `shell_ask()`. It holds the device with `vfs_bdev_change_begin()`. Repairs: FSInfo and the clean
  bit; a FAT copy from a sound primary; a chain cut at the first bad link, with the size set to match; lost chains saved as
  `FOUND.000/FILE0000.CHK`. Two names on one chain: the second gets its own copy of the clusters when there is room, or stays
  reported. Nothing is ever deleted. Writes are ordered so that a pull at any write leaves the volume no worse, and the test
  pulls it at every write, as `test_fatfs` does.
- **Rules for a kernel command** (`CLAUDE.md`, the shell): prints on `curTask->con`, no shared statics, `shell_ask()`, returns
  when interrupted. Status 0 clean or repaired, 1 problems left, 2 usage or trouble. `kalloc()` is checked, and the FAT is read
  in chunks: the owner's stick has 118 GB. A damaged volume must never panic the kernel: fuzz it (`tests/host/test_fatfuzz.c`
  shows how) and compare verdicts with `fsck.fat -n` on the damaged images.
- **Docs:** `docs/GUI.md`'s advice to check a stick on another computer also names `fsck` (that one sentence, nothing more).

This tool writes the owner's own media. It gets the strictest review.

### sys: top, watch, man

- **`top`:** a live view on the alternate screen, in raw mode, using only the ANSI subset of `include/surfos/tty.h`, so it works
  on a console, in the Terminal and over telnet. Sorts by CPU, memory, pid. `-d seconds`, `-n count`. Plain repeated reports when
  standard output is not a terminal. `struct procinfo` lacks CPU time and memory, and nothing gives programs the memory totals:
  append fields to the struct, and add `SYS_sysinfo` as call 54 if you need one. The kernel and SurfCPU's check apply.
- **`watch`:** `watch [-n seconds] [-t] command...`, through `surfsh -c`, so kernel commands work. It reads through a pipe,
  redraws on the alternate screen, and ends on `q` or Ctrl+C with the shell's screen back.
- **`man`:** `man name`, through `less` on a terminal, plain when piped. `man -k word` searches the first lines. Pages live in
  `/initrd/man/` (`rootfs/man/` goes into the initrd by itself). Write a page for every program in `/initrd/bin`, every kernel
  command in `shell/main.c`'s table and every surfsh builtin; test programs and groups of like commands may share a page through
  a small alias table. `tests/test_man.py`, in `make unittest`, fails when any name has no page, so the other tracks' tools
  must have theirs by the integration. Until then, skip names that only exist on another track's branch by listing them in one
  place for the integrator to remove.
- **`help`:** one line pointing at `man`, if that breaks no check.

### net: telnet and ftp

- **`telnet`:** `telnet host [port]`, in raw mode. The client's side of RFC 854 in a host-tested module: ECHO, SUPPRESS-GO-AHEAD,
  BINARY, NAWS with the window's size. Ctrl+] gives a small prompt (`quit`, `status`, `send ayt`). Restores the terminal however it
  ends. Works against SurfOS's `telnetd` and a scripted host server.
- **`ftp`:** `ftp [-n] [host [port]]`, as a prompt or scripted from standard input: `open user ls dir cd pwd get put mget mput
  lcd delete mkdir rmdir rename size binary ascii reget status quit help`. Passive only (EPSV, then PASV). Anonymous by default. A
  password is asked without echo, never taken on the command line, and never printed or kept. Replies are parsed with bounds,
  multi-line ones too. Names from a server's listing are untrusted for `mget`. A data connection only to the server's own address.
  Overwriting goes through saveutil. Reuse `user/ftpd/ftp.c`'s parsing where it fits.
- **Testing:** the guest has no loopback, so tests reach SurfOS's own servers by the hairpin through QEMU's forwarded ports
  (`10.0.2.2:<forwarded port>`) or a scripted server in the harness. `q.ports` has the ports.
