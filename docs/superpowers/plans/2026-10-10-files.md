# SurfOS File Browser Implementation Plan

> Execute with superpowers:executing-plans; verification uses the real guest.

**Goal:** A usable `files` application, merged into `ai-dev`.
**Architecture:** One standalone libsurf application and a dedicated QEMU test
runner importing the existing boot harness. One Makefile program registration.
**Tech stack:** C, libsurf, ANSI terminal controls, Python/QEMU, Docker toolchain.
**Spec:** ../specs/2026-10-10-files-design.md

## Constraints and review focus

Preserve the concurrent web-browser work. Isolate Docker builds using
`SURFOS_VOLUME=surfos-file-browser-build`. Do not change kernel interfaces.
Test stale selection after editing, terminal ownership across child exit,
root/empty-directory boundaries, paths with spaces, and fragmented mouse input.

## Execution notes

- Worktree: `codex/surfos-file-browser`, forked from `ai-dev` at `1dcf4f4`.
- The initial guest test failed on the missing `files` command, then the first
  complete implementation passed 42 integration checks.
- Review: a fresh reviewer identified a false-success message when the current
  directory disappeared while editing. A separate guest reproduction confirmed
  it. The refresh result now preserves that failure.
- A guest reproduction also confirmed that mouse release erased action errors.
  Releases are now ignored before clearing messages; the integration test covers
  the press/release pair.
- Platform decision: serial/Telnet SGR clicks and full native keyboard navigation;
  native pointer input requires a separate kernel driver. This preserves the
  application's isolation from concurrent web-browser development.
- Final interaction check: blank footer space incorrectly triggered Quit. A guest
  reproduction confirmed it; click targets now cover only their visible labels.
  The permanent integration suite includes the regression.
