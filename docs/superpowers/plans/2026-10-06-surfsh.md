# Brief: surfsh, the SurfOS shell

Requested by the owner on 2026-10-06, with a prompt design specification (summarised
below). SurfOS (branch `ai-dev`) boots on the Lenovo IdeaPad 3 15IIL05 into four ring-0
kernel shells, one per console (F1 to F4). This work makes the shell a program, as `bash`
or `sh` is on Linux: `/initrd/bin/surfsh`, which `init` starts on every console. It gives
it the SurfOS prompt, Tab completion and a pager, and changes the banner to SurfOS 1.0.

## The prompt

From the owner's specification (2026-10-06):

* The working directory as breadcrumbs, `▸` (U+25B8) between the names, no leading `/`:
  `/initrd/bin` is `initrd ▸ bin ≋>`. The root is `SURF ≋>`. No `~`: SurfOS has no home
  directories (and no users), so a shell starts at `/`.
* The wave `≋` (U+224B) and one state character before `>`: `≋>` normal, `≋!>` the
  previous command failed, `≋#>` elevated, `≋@>` remote (the host name first), `≋?>`
  diagnostic. Priority: diagnostic, elevated, remote, failed, normal; one state only.
* Long paths: names on the left become `…`; at most 5 items (`prompt.max_depth`) and at
  most half the terminal's width.
* ASCII fallback: `initrd > bin ~>` (`prompt.unicode = off`). Colour is an enhancement;
  the symbols always carry the state.
* One renderer, `prompt_render()` in `shell/prompt.c` (`include/surfos/prompt.h`), used by
  both shells and tested on the host (`tests/host/test_prompt.c`).

What the states mean in SurfOS: surfsh runs in ring 3 and shows `≋>` or `≋!>`. The
kernel's ring-0 shell has system privileges and shows `≋#>`; when `init` falls back to it
because surfsh cannot run (missing, or crashing again and again), it is a recovery console
and shows `≋?>`. SurfOS has no remote sessions yet, so `≋@>` is drawn only in the tests.

## Design

* **The kernel's commands stay in the kernel.** The 67 commands of the ring-0 shell
  (`lsblk`, `fdisk`, `mount`, `ifconfig`, `ps`, `dmesg`, ...) are not rewritten as programs.
  surfsh runs them through `SYS_kcmd` in its own task, as the ring-0 shell did, and lists
  them through `SYS_kcmdinfo` (`include/surfos/kcmd.h`). They return a status now (0
  success, 1 failure, 2 usage), which the prompt shows. Their output can be redirected
  (`lspci > /data/lspci.txt`): the kernel keeps it in memory while the command runs
  (`console_capture_begin()`) and writes it to the caller's descriptor 1 afterwards.
* **Which command runs:** surfsh's own (`cd`, `pwd`, `exit`, `help`, `history`, `set`,
  ...), then the kernel's, then a program in `/initrd/bin`; a name with a `/` is a path.
  This is the ring-0 shell's order, so `ls`, `cat`, `cp` are the kernel's as before; the
  programs of the same names stay reachable by path (`/initrd/bin/ls -la`).
* **The ring-0 shell remains**, as the recovery console and on purpose: `shell=kernel` on
  the kernel command line (a GRUB menu entry) starts it on every console.
* **The console draws UTF-8.** The cells keep one byte, now a code page 437 character:
  VGA text mode shows it with its own font, the framebuffer with Spleen's glyphs for the
  same characters. SurfOS's symbols take three code page 437 places whose VGA glyph is
  close: `▸` at 0x10 (VGA ►), `≋` at 0xF7 (VGA ≈), `…` at 0xF9 (VGA ∙); the framebuffer
  draws the real symbols there (`▸` and `≋` are drawn for SurfOS; Spleen has no glyphs for
  them). A character outside the set is `?`. Bytes that are not UTF-8 are taken as code
  page 437, as programs of 2004 meant them. Accented names (`café.txt`) now show. The
  serial port passes UTF-8 on; `ascii` on the kernel command line makes `TTY_CAPS` say no
  UTF-8, and surfsh then draws the ASCII prompt.
* **The pager** pauses only where a task may wait (task context, interrupts on, no mutex
  held), never in raw mode, and only for the task that asked and the tasks it started.

## Rules for every track

* Work only in your worktree and branch; another track's files are off limits, except
  where this brief names a shared file (the harnesses' `SMOKE` lists: add your steps in
  one block of your own).
* Every commit builds and passes `make unittest` and `make test-all`; a change to the
  console, the terminal, the USB path or `profile=laptop` also passes `make test-usb` at
  -O0 and -O2. Use `SURFOS_VOLUME=surfos-<track>` with `devenv/build.sh`.
* Keep the 2004 file headers and style; new files get the same header block with the date.
* Small commits, one topic each, ending with the co-author line. Never push; never touch
  `master`, `04-source-recovered/` or `01-scans-original/`.
