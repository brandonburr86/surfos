# Brief: Wundertow's milestones 2 and 3, side by side

## The request

The owner, 2026-11-01: build milestones 2 and 3 of the web browser in a window, in parallel. Milestone 1 is
`2026-10-25-browser.md` (W1-W7), merged into ai-dev as 52d4361. That brief's decisions stay: a ring 3 program, no
new system call unless a stage below names one, Undertow's HTTP, TLS and settings, integers only in layout and
painting, every allocation checked, past a limit the page stops with a notice.

**Tracks:** `web/m2` in worktree `../06-restoration-wt-m2`, Docker volume `surfos-wt-m2`; `web/m3` in worktree
`../06-restoration-wt-m3`, Docker volume `surfos-wt-m3`. Both are cut from this commit of ai-dev. Timing-sensitive
suites go through `06-gates/suite-lock.sh` (2 slots), as `06-gates/gate.sh` does. The integrator merges `web/m2`
first and `web/m3` after it, on an integration branch, runs the whole suite, and lands them on ai-dev. Nothing is
pushed; merging and pushing are at the owner's word.

## Who owns what

Both tracks edit `user/wundertow/`. To keep the merge small:

| Files | Owner | The other track |
|---|---|---|
| `browser.c/.h`, `main.c`, the toolbar, keys, requests | M2 | M3 adds its one key or setting at the end of a list, nothing else |
| `user/undertow/http.c` (the additive option), loading, new `image*.c`, `form*.c` | M2 | leaves them alone |
| new `css.c/.h`, `docstyle.c` | M3 | leaves them alone |
| `font.c/.h`, text measuring and line breaking in `layout.c`, text drawing in `paint.c` | M3 | measures text only through `font.h`; a width it needs is one new call there (`wf_width()`) |
| `doc.c/.h` | shared | M2: forms and images. M3: a call into `docstyle.c` where a box or run is made. Keep each hunk small |
| `layout.c` outside text, `paint.c` outside text | M2 for images and fields | M3 for margins and alignment |
| `tests/fixtures/wundertow/` | new files only | M3 regenerates `*.layout` when the default font changes, last; the integrator regenerates them after the merge |
| `Makefile`, `CLAUDE.md`, `docs/UNDERTOW.md`, `docs/GUI.md` | shared | add, do not reflow |

New struct fields go at the end of their struct. Neither track renames or moves code it does not need to.

## Milestone 2 (`web/m2`)

| Stage | What |
|---|---|
| 2.1 Decoders | BMP, GIF (first frame), PNG (with its own inflate), then baseline and progressive JPEG, each `bytes -> 0x00RRGGBB` in integers: `image.h`, `image_*.c`, host-tested, with truncated, oversized and corrupted files of every format. Limits: 4096 pixels a side, 16 megapixels, a page's decoded images 32 MB; past a limit the alt text's frame stays |
| 2.2 Bytes that are not text | an additive option in `http.c` for responses that are not text. Undertow's and fetch's behaviour stays byte-identical |
| 2.3 The loader | a helper process (wundertow itself, through `spawnx` and a pipe) loads pages and images; the window answers meanwhile, Stop in the toolbar kills the helper, a new load replaces the old. A helper that dies is a failed load, never a dead window |
| 2.4 Images on the page | loaded after the page, a few at a time; the frame is the image's size from the attributes, else from the image once known, and the page is laid out again without moving what is being read; scaled in integers; counted in `WB_HISTORY_BYTES`. An https page's image over http is not loaded, as Undertow refuses HTTPS to HTTP; an http(s) page never reads a file |
| 2.5 Reading | find in the page (Ctrl+F, Enter and Shift+Enter, Escape); links by keyboard (Tab, Shift+Tab, Enter, scrolled into view, drawn focused); visited links in this run only, written nowhere |
| 2.6 GET forms | the page model of forms; fields usable by pointer and keyboard (text, checkbox, radio, select, text area, buttons); a submit by the person only, as a GET with the standard's encoding, through `wb_go`'s rules. A POST form says it was not sent. A form with a password field is not sent over GET, whatever the scheme: a password never goes into an address or the history |
| 2.7 Tests and docs | screen checks in `tools/gui_apps_web.py`, also the scroll bar's thumb dragged, which milestone 1's acceptance test wanted and did not get; `tools/qemu-web.py` checks; docs |

## Milestone 3 (`web/m3`)

| Stage | What |
|---|---|
| 3.1 The parser | `css.c/.h`: tolerant tokens, rules, selectors (type, class, id, descendant, child, grouping, `:link`, `:visited` as `:link`), specificity, `!important`, shorthands for what 3.2 uses. Bounded: bytes, rules, selectors a rule, depth. Anything it does not know is skipped, as the standard says. Host-tested with malformed sheets |
| 3.2 The cascade | `docstyle.c`: `<style>` and `style=` onto boxes and runs: `color`, `background-color`, `display:none` and block/inline, `font-weight`, `font-style`, `text-decoration`, `margin-*`, `padding-*`, `text-align`, `font-size` when 3.4 can show it. HTML's own attributes stay, below the page's CSS. Undertow's text does not change |
| 3.3 Sheets from the network | `<link rel=stylesheet>` through M2's loader: same limits as a page, 1 MiB; never across HTTPS to HTTP, never a file from an http(s) page; no `@import` chains past one level, no `url()` loads. It needs stage 2.3: merge `web/m2` into `web/m3` at the commit that finishes 2.3, or leave this stage to the integration and say so |
| 3.4 Sizes | the console's 8x16, 12x24 and 16x32 (`driver/font*.c`, in libsurf) behind `font.h`: headings and `font-size` by real sizes, not 2x; the base size a setting, by the desktop's font by default |
| 3.5 Proportional | glyphs of the existing Spleen fonts trimmed to their ink, with a width table a tool generates (`tools/`), so no new font data and no new licence; a different font needs the owner's word. Monospaced runs (`WS_MONO`, pre) stay in the cell font. Integers only. Every caller measures through `font.h` |
| 3.6 Tests and docs | fixtures regenerated and read by eye; screen checks moved to where the layout now puts things; docs |

## Checks

- **Every commit** builds and passes `make unittest` and `make test-all` at -O0 and -O2.
- **Commits that touch Undertow's files** also pass `make test-web` at -O0 and -O2, and keep `test_undertow_html`'s
  text byte-identical.
- **The program's commits** also pass `make test-usb` at -O0 and -O2 before the track reports (run it at each stage's end).
- A commit to `kernel/`, `fs/`, `mm/` or `shell/` also passes `make -C surfcpu test-os-qemu`.
- **On the Mac:** `SURFOS_VOLUME=<the track's volume> ./devenv/build.sh ...`, or `06-gates/gate.sh wt-m2 surfos-wt-m2 <tag>
  <commit>`, which leaves the worktree on a detached HEAD.
- **Review:** each stage that parses what a server sends (2.1, 2.2, 2.3, 2.6, 3.1, 3.3) has an independent read-only review of its
  diff, then a fix round, and the fix round's diff is reviewed again until a round finds only nits.
- **Public sites and the laptop** are not part of these checks. They are the owner's to run: say so in the report.

## The acceptance tests

- **M2:** on the screen, a page from the test stick shows a PNG, a JPEG, a GIF and a BMP where their pixels should be; a
  corrupted image keeps its frame and the page; Stop ends a load that never finishes while the window answers; Ctrl+F
  finds a word and shows it; Tab reaches a link and Enter follows it; a visited link changes colour; a GET form typed and
  submitted reaches the test server with the right query, and a POST form and a password form do not.
- **M3:** a page whose `<style>`, `style=` and linked sheet set colours, `display:none`, weight, style, margins and
  alignment shows them on the screen; headings have real sizes; running text is proportional and code stays monospaced;
  a malformed sheet changes nothing else on the page.

## Decisions made in milestone 2

Nobody could be asked while it was built, so these were taken and are the integrator's to overturn:

- **A form runs from its tag to its end tag, or holds what names it by `form=`.** That is the standard's form element
  pointer without the ancestors. A browser also has in a form what comes after `</form>` inside an element left open in it.
  Three rounds of following that with counts of open elements refused valid pages and lost fields; what it takes is a
  tree of elements with the adoption agency and foster parenting, which this page model does not have. So on mis-nested
  pages a control can be in no form here. It can only ever send less, and pages that nest as they should see no difference.
- **What this browser does not follow keeps a form from going, rather than sending another form than the page's:** the
  list is in `docs/UNDERTOW.md`, "Forms", and "Not yet" says what is left. On that side it errs, by design.
- **A plain ASCII page that says nothing of its charset** sends a form in windows-1252, a browser's default, and
  `ut_html_declared()` was added to `html_scan.c` for it. Undertow does not call it.
- **`Makefile`'s `DEPS` lacked `WUNDERTOW_OBJ`**, so that a header changed under built objects rebuilt none of them. Milestone
  3 lives with the same line until this merges: a stale object shows as a struct's stride gone wrong.
