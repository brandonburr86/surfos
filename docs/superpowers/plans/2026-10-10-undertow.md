# Undertow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a native SurfOS console browser with HTTP, verified HTTPS, readable HTML, numbered links, navigation, paging and search.

**Architecture:** A ring-3 C program owns browsing, rendering and TLS. Extend the kernel only for bounded DNS lookup and strict entropy. Keep protocol parsers independent of network and terminal I/O so host tests exercise the same code that ships.

**Tech Stack:** Existing i486 freestanding GCC build, libsurf, Mbed TLS 3.6.7 candidate from the 3.6 LTS branch, Mozilla-derived CA bundle, Python fixtures, QEMU and OVMF.

**Spec:** [Approved Undertow design](../specs/2026-10-10-undertow-design.md).

## Global Constraints

- Both HTTP and HTTPS are acceptance requirements; JavaScript execution is excluded.
- Keep 32-bit x86, the existing kernel architecture and both boot profiles; do not change Wi-Fi association behavior.
- Enable TLS 1.2 and 1.3, SNI, certificate-chain verification, hostname verification, certificate validity dates, and HTTP/1.1 ALPN.
- No insecure verification bypass, automatic HTTPS-to-HTTP fallback, early data or session resumption.
- Keep up to 16 history entries, with an 8 MiB aggregate budget for rendered text, links and metadata.
- Initial limits: 2,048 bytes per URL, 32 KiB of response headers, 1 MiB of received body, 512 KiB of rendered text, and 256 links per page.
- DNS within 5 seconds, TCP connection within the existing 10-second bound, TLS handshake within 20 seconds, reads and writes after 15 seconds without progress, and a 60-second total load deadline across redirects.
- Package roots at `/initrd/etc/ssl/cert.pem`; test-only roots belong exclusively to test images.
- Retain license and provenance for dependencies; pin downloads by checksum before consuming them.
- Follow `CLAUDE.md`: build and pass `make test-all` before code commits, plus `make unittest` and O0/O2 USB tests for affected laptop functionality. Group edits into testable commits to avoid rerunning the same full suite unnecessarily.
- Build USB images only as files. Physical installation and reboot require owner coordination.
- Approved for implementation with subagents by the owner on 2026-10-10.

## Review Focus

- TCP or TLS splits a header, UTF-8 sequence or HTML entity at any byte: parsing must preserve its meaning (Tasks 4–6).
- A user goes back, then attempts an invalid or failing address: current page and forward history must survive (Task 7).
- A timer wraps while a peer sends one byte just before each idle timeout: the total deadline still ends the request (Tasks 1 and 4).
- One console browses while another joins Wi-Fi or looks up a hostname: no shared browser state, leaked socket or weakened entropy contract (Tasks 1–2 and 8).
- Long titles, addresses, control sequences and overlong command lines arrive together: output stays safe and the command tail never executes (Tasks 3, 6–8).

## File Layout and Shared Contracts

New kernel files: `net/dns_wire.c` for pure DNS packet handling, `kernel/websvc.c` for the two new system calls. Keep strict entropy in `lib/crypto/random.c`, alongside the existing hardware access, without changing `crypto_random()`'s contract.

New application directory `user/undertow/`:

| File | Responsibility |
| --- | --- |
| `url.h`, `url.c` | Parsed URLs, resolution and request-target formatting |
| `transport.h`, `transport.c` | TCP/TLS connection and deadline-aware I/O |
| `tls_config.h`, `tls_platform.h`, `tls_platform.c` | Vendor configuration, entropy and clock adapter |
| `http.h`, `http.c` | HTTP framing and fetch with redirects |
| `html.h`, `html.c` | Text, title, links and anchor extraction |
| `session.h`, `session.c` | Owned pages, navigation, reading positions and search |
| `view.h`, `view.c` | Terminal-safe wrapping and one-screen views |
| `main.c` | Options, commands, welcome, errors and exit |

Use explicit sizes, caller-owned error buffers and integer return codes. Unless specified otherwise, application functions return 0 on success and -1 on failure; an error buffer receives a bounded, terminal-safe explanation. All outputs remain empty or unchanged on failure. No library function exits the process.

`struct ut_url` contains `char text[2049]`, `host[254]`, `target[2049]`, `fragment[2049]`, `unsigned short port`, and `int secure`. `target` contains path and query, never fragment. URL arguments point to heap or existing objects rather than adding these large structures to nested stacks.

`struct ut_clock` holds `int rtc_offset_minutes`, `int override_set`, `time_t override_utc`, and `unsigned int override_ticks`. UTC equals RTC minus offset, or override plus elapsed uptime. Offset is in [-840, 840].

`struct ut_document` owns `char *text`, `size_t text_len`, `char *title`, a dynamic array of `{char *label; char *url;}` links, and `{char *name; size_t offset;}` anchors; it records their counts, owned allocation bytes and truncation flags. Limit anchors to 256 as well as links. Text offsets are UTF-8 byte offsets; view code handles display columns.

`struct ut_page` owns a final `struct ut_url`, `struct ut_document`, `int status`, `int verified`, and `size_t position`. `struct ut_session` owns up to 16 page pointers, count, current index, aggregate allocated bytes and the last search string. Ownership transfer happens only on successful navigation.

## Plan Review and Execution

The owner approved the design on 2026-10-10. The next choice is execution:

- **Native:** this agent implements all tasks in this chat, followed by an independent whole-change review. Recommended for lower overhead and consistent handling of the closely shared interfaces.
- **Subagent-driven:** a fresh implementer and reviewer work through each task, with a final whole-change review. More review checkpoints and more context overhead.

Preserve the chosen method throughout execution. Detect existing worktree isolation at execution time and use the repository's current branch as the starting point; do not silently start from the restoration-only default branch.
