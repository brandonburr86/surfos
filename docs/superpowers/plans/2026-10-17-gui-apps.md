# Brief: desktop menus, Notepad and Files (2026-10-17)

## The request

The owner, 2026-10-17: build out the core of the `gui` desktop (which has Calculator and
Sketch) with more comprehensive menus and some basic applications: a file editor like
Notepad, and an application that shows the file structure. They want to open an
application to edit files, choose a file, and have it open in a Notepad-style editor,
everything SurfOS-themed. The work is done in its own worktree (branch `gui/apps`, from
ai-dev b02091b), apart from the other agents' branches.

## What gets built

* **Window manager.** Windows can be minimized, maximized (and restored) and, for the
  document windows, resized from a corner grip. A taskbar shows a button for each open
  window and a clock. Desktop tiles open the four applications.
* **Menus.** The menu bar becomes ≋ SurfOS, File, Edit, Apps, Window and Help. The menus are
  tables, so items can be disabled when they do not apply, show their shortcut, and be
  separated into groups. The keyboard runs them as before (Ctrl+G, the arrows, Enter, Esc).
* **Notepad.** One document at a time: New, Open…, Save, Save as…, undo and redo, cut,
  copy and paste, select all, find, go to line. It has a line-number gutter, a scroll bar,
  mouse selection (drag, double-click a word) and a status bar. Line ends are kept: a file
  whose every line ends in CRLF is shown with LF and saved with CRLF again. A file with a
  NUL byte is refused as binary. The limit is 256 KB. A read-only volume (the initrd, the
  flashed SURFOSUSB stick) is reported, and Save as… is offered. Saving works like
  `edit`'s: write `<file>.tmp`, fsync it, rename it over the file, and write in place only
  where the file system cannot rename. Closing, opening another file or leaving the
  desktop with unsaved changes asks first: Save, Don't save, or Cancel.
* **Files.** An expandable tree that starts at `/`, with folders first and each row's size
  and date. Double-click (or Enter) opens a folder or opens a file in Notepad. The toolbar
  has Open, New file, New folder, Rename, Delete (after a confirmation, and only a file or
  an empty folder) and Refresh. USB volumes that are not mounted are listed at the root
  with a Mount button. Mounted USB volumes can be ejected. Mount and Eject run the shell's
  own `mount` and `eject` commands with their output captured (`console_capture_begin()`),
  so the storage rules (`bdev_mount_readonly()`, busy volumes, the flush before "safe to
  remove") are the same code. Nothing is mounted unless the user clicks Mount.
* **Dialogs.** Message, confirmation, text input, and the Open and Save as file choosers
  (folder list, Up, a file-name field).
* **Theme.** The existing palette (navy, ink, teal, foam, paper, coral), the ≋ mark, small
  pixel-art icons for folders, documents, drives and the applications.

## Design

* `include/sys/gui.h` stays the pure model: no hardware access and no allocation. File access
  goes through `struct gui_fs`, which the model calls only from its key and pointer
  handlers, never while drawing. `shell/guifs.c` implements it on the VFS, and the host test
  implements it in memory.
* `shell/guipriv.h` is what the desktop's files share. `shell/guidraw.c` holds the drawing
  kit, icons and theme. `shell/guicore.c` holds the window manager, menus, desktop,
  Calculator, Sketch, About, Settings and Help. `shell/guinote.c` holds Notepad,
  `shell/guifiles.c` holds Files, and `shell/guidialog.c` holds the dialogs and choosers.
* `shell/gui.c` adds Home, End, PgUp, PgDn, Insert and Delete to its key parser. It sends
  the arrows to the model while Notepad, Files, a dialog or a menu has them (otherwise they
  still move the pointer). It also sets the model's clock and its millisecond time, which
  is used for double-clicks.
* Ctrl+C copies in Notepad. Everywhere else it leaves the desktop, as before, but asks
  first when Notepad has unsaved changes. Ctrl+Q always leaves the desktop, also asking
  first.
* Everything lives in the `gui_state` that `cmd_gui` allocates for one run: no statics, so
  nothing is shared between consoles.

## Checks

* `tests/host/test_gui.c`: Notepad editing, undo and redo, the clipboard, line ends, binary
  refusal, find, saving and the unsaved-changes guard; the Files tree, its actions and the
  choosers against an in-memory file system; the menus' enabled items; rendering bounds at
  640×400, 960×540 and 1280×800.
* `tools/gui_scenario.py` (`qemu-usb.py --scenario gui`): the existing desktop checks on the
  new layout. A FAT32 data stick is attached: Files mounts it, a file is opened, edited and
  saved in Notepad, Save as writes a second file, and Eject says it is safe to remove. The
  stick image is then checked on the host (the files' bytes, and `fsck.fat` when there is
  one).
* The whole suite at O0 and O2: unittest, smoke (test-all) and test-usb, then independent
  reviews, then the merge into ai-dev (not pushed).
