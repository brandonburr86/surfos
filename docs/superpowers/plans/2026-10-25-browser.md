# Brief: a web browser in a window (wundertow; track C's C13)

## The request

The owner, 2026-10-25: a web browser usable within the desktop. Start basic, with HTML rendering and
scrolling, and build from there. This is the "graphical Undertow" that the windows-for-programs brief
(`2026-10-25-app-windows.md`, C13) listed last. The lead of tracks A/B/C handed it over the same day.

**Where:** branch `web/main`, worktree `../06-restoration-web`, based on `ai-dev`. Docker volume
`surfos-web`. Timing-sensitive suites (test-all, test-web, test-tcp, multi-scenario test-usb) run through the
team's suite lock as `web`. The window front-end needs track C's platform: stages C1–C7, `SYS_winopen`,
`SYS_winctl` and libgui's `gw_*` calls. It joins once that platform is on ai-dev, and until then
everything else is built and tested without a window. Merged into ai-dev at the owner's word, after track
C's platform, by the 2026-10-25 protocol. Nothing is pushed.

## Decisions

- **A program, not a kernel app.** The browser parses what any server sends. It runs in ring 3 like
  Undertow, and a bug costs only its window. The kernel gains no browser code and no new system call.
- **The program:** `wundertow` (track C names windowed programs wcalc, wdemo), in `user/wundertow/`, with
  an explicit object list. Undertow's directory is a wildcard, and a second `main()` there would break it.
  Like `/bin/fetch`, it links Undertow's url, http, transport, tls_platform, config and util. So HTTPS is
  Undertow's, unchanged: every certificate check, no bypass, no fallback to http, RDRAND only, the clock
  rules (docs/UNDERTOW.md).
- **One HTML scanner.** html.c's tokenizer, character references and charset rules move into
  `user/undertow/html_scan.c`, which html.c and the browser both use. The first commit is a pure move:
  Undertow's text stays byte-identical (21 fixture pages, 672 host checks, the UBSan copy, test-web).
- **A box tree, not flat text.** Undertow's document is readable text with numbered links. The browser's is
  block boxes (paragraphs, headings by level, list items with their markers, quotes, pre, rules, tables,
  rows, cells), each holding blocks or styled inline runs (bold, italic, monospace, underline,
  strike-through, sub/sup, size, colour, the link it belongs to, images by their alt text). The HTML
  standard's implied ends and scopes come from html.c's rules.
- **Layout and painting in integers.** Fonts sit behind a small interface. Today there is one font, the
  console's 8x16 (code page 437, as the desktop draws it). Bold, italic, underline and 2x headings are
  drawn from it. Track A's and C9's larger fonts, and later proportional ones, plug in there. No floating
  point anywhere, as libgui's header requires.
- **Limits are Undertow's:** a body of at most 1 MiB, 512 KB of text, 2048 links, 2048 anchors and 1 MiB
  of link strings. The browser adds caps on boxes and runs. Past any limit the page stops, with a notice.
  Every allocation is checked, and an allocation failure is an error page, never a crash.
- **file: pages,** for local HTML (a stick, `/initrd/www`, the screen tests). Only an address the owner
  typed, or a link on a file: page, opens one. An http(s) page never does.
- **Loading blocks in milestone 1** (at most Undertow's 60 s). The window says "Loading…" first. A helper
  process with Stop comes in milestone 2.
- **The look is the desktop's:**
  - a toolbar of BAND with SHELL buttons: Back, Forward, Reload;
  - an address field like the dialogs' text fields;
  - the page on the text background FFFDF5, in INK, with links in TEAL, underlined;
  - a 12 px scroll bar and a 22 px status bar.

  A page's own colours (`bgcolor`, `text`, `link`, `<font color>`) are kept. Every window fits 640x400.
- **Docs** go in docs/UNDERTOW.md (a section for the window), CLAUDE.md and GUI.md. No ARCHITECTURE.md
  number is needed.

## Stages

Each stage is a series of small commits that build and pass the checks below.

| Stage | What | Where |
|---|---|---|
| W1. One scanner | html.c's tokenizer, charsets and character references moved, output unchanged; the attribute set grown for the browser (src, width, height, color, bgcolor, align, colspan, ...) | new `user/undertow/html_scan.c/.h`, `user/undertow/html.c` |
| W2. The document | tokens to the box tree: blocks, runs, styles, links, anchors, images, page colours, the title, the limits | new `user/wundertow/doc.c/.h`, new `tests/host/test_wundertow_doc.c` + fixtures |
| W3. Layout | the tree at a width: lines, wrapping, margins, indents, list markers, pre, rules, simple tables; a display list with link boxes and anchor positions | new `user/wundertow/layout.c/.h`, `font.c/.h`, `tests/host/test_wundertow_layout.c` |
| W4. Painting | the display list into a 0x00RRGGBB image at a scroll position, clipped: glyphs with their styles, rules, bullets, cells, image boxes | new `user/wundertow/paint.c/.h`, `tests/host/test_wundertow_paint.c` |
| W5. The browser | address field, history of pages with their scroll positions, scrolling, hovering, clicking, the chrome; driven by events | new `user/wundertow/browser.c/.h`, `tests/host/test_wundertow_browser.c` |
| W6. The program | `wundertow --layout ADDRESS` (the layout as text) and `--render ADDRESS FILE.bmp`; the window once track C's platform has landed | new `user/wundertow/main.c`, Makefile, initrd |
| W7. Tests and docs | test-web checks of `--layout` (HTTP, HTTPS, refusals); a guiapps screen module (load, a heading's glyphs, a link, scrolling, resizing); docs; the "Run program…" entry (asked of the lead) | `tools/qemu-web.py`, new `tools/gui_apps_web.py`, docs |

**Milestone 1 ("basic")** is W1–W7:
- headings, paragraphs, bold, italic, underline, strike-through and code;
- links you click, with the address shown in the status bar;
- lists with bullets and numbers, quotes, pre, rules, line breaks, centring, the page's colours;
- simple tables;
- images as their alt text in a frame;
- the title in the window's title;
- scrolling by keys (arrows, Page Up/Down, Space, Home/End), by the scroll bar, and by the wheel once
  track C's C8 delivers it;
- reflow on resize;
- back, forward and reload;
- http, https and file pages.

**Later milestones:**
- **M2:**
  - images: BMP, GIF, PNG, then JPEG, with an additive option in http.c for responses that are not text;
  - a helper process for loading, with a Stop button;
  - find in the page, links by keyboard (Tab, Enter), visited links;
  - GET forms.
- **M3:**
  - simple CSS: colours, display:none, weight and style, margins, text-align;
  - the larger and proportional fonts.

## Checks

- **Every commit** builds and passes `make unittest` and `make test-all` (-O0 and -O2).
- **Commits that touch Undertow's files** (W1, W2's scanner use) also pass `make test-web` at -O0 and -O2.
- **From W6 on, the program's commits** also pass `make test-usb` at -O0 and -O2.
- **On the Mac:** `SURFOS_VOLUME=surfos-web ./devenv/build.sh …`. Before test-usb, export the disk images
  to build/docker (CLAUDE.md, test-usb-needs-make-images).
- **The acceptance test of milestone 1:**
  - the host tests of W2–W5;
  - test-web's `--layout` checks;
  - on the screen (guiapps, once the window exists): a page from the test stick shows its heading and a
    link in their colours, the link opens the next page, Back returns, Page Down and the scroll bar move
    the text, and a resize reflows it.
- **At the end,** an independent review; each finding gets a check.

## Rules

- **CLAUDE.md's rules:** Undertow's validation section, the storage rule for anything that writes a file
  (only `--render`'s file), and small commits with one topic each. New files get the header block with
  their date.
- **Untrusted text:** nothing from a page is printed or put in a title raw. Status-bar and title text go
  through `ut_safe_text()`, and every string's size is bounded.
- **Nothing starts by itself.** The browser loads only what the owner typed or clicked.
