# Brief: the desktop's applications (2026-10-17)

## The request

The owner, 2026-10-17: "Now go and start building out an array of useful applications that are
accessible in the GUI." The `gui` desktop (docs/GUI.md) has Calculator and Sketch (10/10/26) and
Notepad and Files with a window manager (10/17/26, gui/apps). This adds eight applications, built in
four tracks at the same time, on branch `gui/suite` (from ai-dev 0efbade), apart from the other
agents' branches, and merged into ai-dev only at the owner's word.

## The applications

| Application | What it does | Track |
| --- | --- | --- |
| **Terminal** | surfsh, the SurfOS shell, in a window, on a pseudo-terminal: every command, as on F1-F4 | TERM |
| **System Monitor** | the tasks (end a program), memory, and the machine | SYS |
| **Disks** | the block devices as lsblk lists them, how full the mounted ones are, Mount and Eject | SYS |
| **Log** | the kernel log (dmesg), following what comes, with find | TOOLS |
| **Clock** | the time and the date large, a month's calendar, a stopwatch and a timer | TOOLS |
| **Character Map** | the console's 256 characters, to copy into Notepad or the Terminal | TOOLS |
| **Image Viewer** | BMP pictures, fitted or zoomed; Sketch saves and opens BMP | MEDIA |
| **Hex** | any file's bytes, in hexadecimal and as characters | MEDIA |

What each must do, at least:

* **Terminal (TERM).** A session of `/initrd/bin/surfsh` on a free pseudo-terminal (kernel/pty.c),
  started when the window opens. Its output is read every frame (gui_tick, `term_read`, never
  waiting) into a screen of cells that understands what SurfOS's programs print: the console's ANSI
  subset (include/surfos/tty.h lists it; surfsh's prompt, `edit`, the pager, colours, UTF-8 as the
  console decodes it). A scrollback of at least 500 lines, with the scroll bar and the wheel; the
  window's size (resizable, maximize) is the terminal's size (`term_resize`, PTY_SETSIZE). Keys go to
  the session as a terminal sends them (the arrows and Home, End, Page Up and Down as escape
  sequences; Ctrl+C reaches the program), every key but Ctrl+G, which opens the menus. Selecting text
  with the mouse and the desktop's clipboard: copy and paste (the menus' Edit items, or a toolbar).
  When the session ends (`exit`), the window says so and offers a new one. Leaving the desktop or
  closing the window ends the session: `busy` asks first.
* **System Monitor (SYS).** Pages for Processes (pid, name, state, console, program or kernel thread;
  sorted; a selection; End task, which asks first, ends a program only: `kill` in struct gui_sys),
  Memory (physical memory, the kernel heap, the DMA heap, as bars and numbers), and System (the
  processor, firmware, profile, display, build, uptime, tasks, timers). It reads them about once a
  second while it is open.
* **Disks (SYS).** Every block device as lsblk shows it (name, size, bus, type, model or label,
  status), the partitions under their disks; for a mounted volume where, and a bar of used and free
  space; Mount and Eject for USB volumes, through struct gui_fs's `mount` and `eject` (the shell's
  own commands, so the storage rules of CLAUDE.md hold). The kernel side is `guisys_disks()`
  (shell/guisys_disk.c).
* **Log (TOOLS).** The kernel log in a scrolling view, read again about twice a second while it is
  open (`log` in struct gui_sys, which gives what is new by `written`); Follow keeps the view at the
  end; find (as Notepad's find bar); a line, or a selection, copied to the clipboard; Home, End,
  Page Up and Down.
* **Clock (TOOLS).** gui_state.time (the CMOS clock, set by shell/gui.c each second): the time large
  and the date; a month's calendar (the month before and after, today marked); a stopwatch (start,
  stop, lap, reset) and a timer (set minutes and seconds, start, a visible alert at zero), both on
  gui_state.now.
* **Character Map (TOOLS).** The 256 characters of code page 437 that the console draws, in a grid;
  the one chosen large, with its code, its Unicode code point and its UTF-8 bytes; Copy puts it on the
  desktop's clipboard (UTF-8), so it can be pasted into Notepad or the Terminal: the laptop's
  keyboard types nothing beyond ASCII.
* **Image Viewer (MEDIA).** BMP files (uncompressed 24- and 32-bit, and 8-bit with a palette; others
  refused, saying why), opened with a chooser (dialog_chooser) or from Files; fitted to the window,
  actual size, zoom in and out, and moving a zoomed picture with the mouse or the arrows; a size limit
  said in the status bar. Sketch gains Save as BMP and Open BMP (its parts of shell/guicore.c are
  MEDIA's).
* **Hex (MEDIA).** Any file, read a page at a time with struct gui_fs's `read_at` (no limit on the
  size): the offset, 16 bytes in hexadecimal, and the bytes as characters; Page Up and Down, Home,
  End, go to an offset, find bytes (text or hexadecimal); read-only.
* Files opens a `.bmp` in the Image Viewer, and a file Notepad refuses (binary) in Hex: the
  integrator adds that once both exist.

## The foundation (the first commit on gui/suite)

* **The table.** `struct gui_app` (shell/guipriv.h) is what the window manager asks of an
  application in a file of its own: its title, icon, size, whether it is resizable and which keys are
  its own, and hooks for opening, closing, drawing, keys, the pointer (press, drag, release, wheel),
  every frame (`tick`), a title of its own, being busy, the answers to its dialogs (`gui_app_act()`),
  its lines in Help, and the Edit menu (`can_edit` and `edit`: Undo to Go to, and their keys Ctrl+Z, Y,
  X, C, V, A, F and L when its key hook leaves them, so Copy and Paste work alike in every window; a
  `goto_label` such as "Go to offset…"). shell/guicore.c holds the table (`suite[]`, window numbers GUI_TERMINAL to
  GUI_CHARMAP), and gives each application its window, its item in the Apps menu, a tile on the
  desktop (two more columns beside the desktop's own four), a button in the taskbar, and its Help
  lines after the desktop's. Ctrl+T opens the Terminal. The desktop's own windows keep their code.
* **The system.** `struct gui_sys` (include/sys/gui_sys.h) is the kernel's side, as struct gui_fs is
  the files': the tasks, memory, the machine, ending a task, the block devices, the kernel log and a
  terminal session. shell/guisys.c implements the tasks, memory, machine, kill and log (with
  `klog_copy()` in kernel/klog.c); the block devices are shell/guisys_disk.c's and the terminal
  shell/guisys_term.c's, stubs until their tracks fill them. The model calls struct gui_sys from its
  handlers and its tick only, never while drawing.
* **The shell.** shell/gui.c sets `g->sys`, the date and time (`g->time`) each second, calls
  `gui_tick(g)` every frame (also while another console has the screen) and `gui_finish(g)` before it
  frees the state.
* **Files.** struct gui_fs gains `read_at` (n bytes from an offset, and the size), in shell/guifs.c
  and the fakes.
* **State.** Each track's state is a struct in a header of its own (include/sys/gui_term.h,
  gui_sysapps.h, gui_tools.h, gui_media.h), embedded in gui_state.
* **Stubs.** shell/guiterm.c, guimon.c, guidisks.c, guilog.c, guiclock.c, guiview.c, guihex.c and
  guichar.c draw a placeholder; the icons are in shell/guidraw.c.
* **Tests.** tests/host/gui_fake.c (an in-memory file system and system, a screen with guard pixels,
  a desktop with both), and one host test per track (tests/host/test_guiterm.c, test_guisys.c,
  test_guitools.c, test_guimedia.c), each built and run by `make unittest` (unittest-gui). The
  existing test_gui.c checks every window, the new ones too, at 640x400, 960x540 and 1280x800. On the
  screen: qemu-usb.py's `guiapps` scenario (tools/gui_apps_scenario.py: one boot, the desktop, then
  each track's checks from tools/gui_apps_term.py, gui_apps_sys.py, gui_apps_tools.py and
  gui_apps_media.py).

## Who edits what

Each track works in its own worktree and branch (`gui/term`, `gui/sys`, `gui/tools`, `gui/media`,
from the foundation), with its own Docker volume, and edits only its own files, so the merges are
clean:

| Track | Its files |
| --- | --- |
| TERM | shell/guiterm.c, include/sys/gui_term.h, shell/guisys_term.c, kernel/pty.c (a kernel-side API for a session; the system calls keep their behaviour), include/surfos/pty.h, tests/host/test_guiterm.c, tools/gui_apps_term.py |
| SYS | shell/guimon.c, shell/guidisks.c, include/sys/gui_sysapps.h, shell/guisys_disk.c, the tasks/memory/machine/kill functions of shell/guisys.c, tests/host/test_guisys.c, tools/gui_apps_sys.py |
| TOOLS | shell/guilog.c, shell/guiclock.c, shell/guichar.c, include/sys/gui_tools.h, log_copy() in shell/guisys.c and klog_copy() in kernel/klog.c, tests/host/test_guitools.c, tools/gui_apps_tools.py |
| MEDIA | shell/guiview.c, shell/guihex.c, include/sys/gui_media.h, Sketch's code in shell/guicore.c (its drawing, its press, its keys), tests/host/test_guimedia.c, tools/gui_apps_media.py |

* A track may add files of its own (a terminal emulator's model, say), and adds a new model file to
  `GUI_HOST_OBJ` in the Makefile; nothing else in the Makefile.
* The shared files (shell/guicore.c beyond MEDIA's Sketch, shell/guipriv.h, include/sys/gui.h,
  include/sys/gui_sys.h, shell/gui.c, tests/host/gui_fake.c and .h) change only where a track must:
  a field at the end of a struct of its own track (gui_sys.h's structs are SYS's), a call at the end
  of struct gui_sys and of the table in shell/guisys.c, a field at the end of struct gui_app, a fake
  at the end of gui_fake.c. Say so in the commit message; the integrator resolves.
* Each track writes what it built for the user guide (keys, limits) in
  `docs/superpowers/plans/2026-10-17-gui-suite-<track>.md`; the integrator puts it into docs/GUI.md.

## The rules (CLAUDE.md, and the desktop's)

* The model is pure: no hardware, no allocation, no blocking; files only through struct gui_fs and
  the system only through struct gui_sys, from the handlers and the tick, never while drawing.
  Everything lives in gui_state (no statics that two consoles could share). gui_state is kcalloc'd
  once: say in the commit message how much a track's state adds.
* Every window fits 640x400 (maximized too); the host tests draw them inside guard pixels.
* The desktop's look: shell/guipriv.h's palette, the drawing kit's toolbar, buttons, scroll bar and
  status bar, the icons' style, the menus' words.
* Keys: an application's keys are in its Help lines; it does not take the desktop's shortcuts (Ctrl+Q,
  Ctrl+G, Ctrl+E, Ctrl+B, Ctrl+K, Ctrl+D, Ctrl+P, Ctrl+O, Ctrl+W, Ctrl+N, Ctrl+T), but for the Terminal,
  whose every key but Ctrl+G is its own.
* Nothing logs what is typed in the Terminal. Never put a Wi-Fi password in a test or a file.
* Kill only your own processes and containers, by recorded PID or by a container whose mount is your
  own worktree; never `pkill -f`, `killall`, or `docker kill` or `stop` by name. Never re-run failures
  with full traces. Never write a disk device; never push; never touch `master`, 04-source-recovered,
  01-scans-original, or another worktree or branch.

## Checks

Each track, before it hands back: `make unittest` (at least `unittest-gui` passing), the kernel built
at O0 and O2 with no new warnings, and `tools/qemu-usb.py --test --scenario gui --scenario guiapps` at
O0 and O2 on a USB image built with `devenv/build-usb.sh` into the track's own `SURFOS_OUT`, its
volume `SURFOS_VOLUME=surfos-gui<track>`. The integrator then merges the tracks into gui/suite (TOOLS,
SYS, MEDIA, TERM), runs the whole suite (unittest, test-all, test-usb at O0 and O2, test-mkusb), has
each track reviewed independently, fixes what the reviews find, and offers the merge into ai-dev.
