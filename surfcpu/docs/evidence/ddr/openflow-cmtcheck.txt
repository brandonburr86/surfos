`.CLKOUT0_DIVIDE (4'd8)`, `.CLKOUT3_PHASE (7'd90)`), which Yosys's JSON writes as bit strings of
their width. The netlist's parameters (surfcpu_arty_a7_top.json, cell u_dram.PLLE2_ADV):

cmtcheck.py's param() takes a 0/1 string as binary only when it has 8 or more characters, so
"10000" (16) reads as ten thousand, "1000" (8) as a thousand, "100" (4) as a hundred and the
phase "1011010" (90) as 1011010.0. The FASM nextpnr wrote for the PLL (its tile at

So the clock tiles are encoded as XAPP888 says, and the FAIL is the check's reading of the
netlist. The fix is the flow track's (devenv/openxc7/cmtcheck.py, param()); it is not changed here.
The 90-degree output stays "unchecked", as cmtcheck intends for any phase other than 0.

The one-off script (run from surfcpu/ in surfcpu-openxc7:2026-10-15 with the build's --json, --placement
and --fasm):
  """One-off analysis (not part of any flow): devenv/openxc7/cmtcheck.py with one change, a
  parameter that Yosys's JSON writes as a bit string (only 0 and 1, any length) read as binary,
  so LiteDRAM's sized literals (5'd16 -> "10000") are not read as decimal numbers."""
  import importlib.util, sys
  spec = importlib.util.spec_from_file_location("cmtcheck", "devenv/openxc7/cmtcheck.py")
  m = importlib.util.module_from_spec(spec)
  spec.loader.exec_module(m)
  orig = m.param
  def param(cell, name, default):
      v = cell.get("parameters", {}).get(name)
      if isinstance(v, str):
          s = v.strip('"')
          if s and set(s) <= {"0", "1"} and not v.endswith(" "):
              return int(s, 2)
      return orig(cell, name, default)
  m.param = param
  sys.argv = ["cmtcheck.py"] + sys.argv[1:]
  sys.exit(m.main())
