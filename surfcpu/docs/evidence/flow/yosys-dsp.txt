Yosys DSP packing silently deletes logic (synth_xilinx, xilinx_dsp pass), 2026-10-15/16
Reported by the io track (surf_video, io commit 534de7b, merged as fde641f); reproduced and
measured here. Scripts under build/flow/dspbug/ (not committed); the reproducer
devenv/openxc7/test/dsp_counter.v and its testbench are committed.

Mechanism (Yosys 0.69 log): "Analysing ... $mul ... for Xilinx DSP packing. preadder
$add$surf_video.v:172 ... ffAD: ..." - the counter's increment hcnt + 1 is taken as the DSP48E1
pre-adder and the hcnt register as its AD pipeline register. The counter then exists only
inside the DSP, so every other reader of hcnt loses its source and is optimized away.

Workaround, demonstrated above: `scratchpad -set xilinx_dsp.multonly 1` before synth_xilinx
(documented in `help xilinx_dsp`: the pass becomes a no-op). Multipliers still map to DSP48E1
(mul2dsp, xc7_dsp_map); only Yosys's packing of registers and pre/post-adders is skipped, so
pipeline registers stay in fabric and wide products add their partial sums in LUTs (the probe's
32x32 multiply: 4 DSP48E1 either way, 507 LUTs instead of 446). tools/openxc7-build.sh uses it
by default (--dsp safe); --dsp full gives openXC7's plain recipe, --dsp none uses -nodsp.

Detection: devenv/openxc7/synthcheck.py compares the synthesized netlist with the elaborated
RTL (proc, flatten, opt -full, wreduce, memory -nomap): flip-flops per instance with credit for
DSP/RAM/SRL registers, large memories against block RAM, outputs that became constant. Every
openxc7-build.sh run applies it (check-synthesis.txt; --expect adds minimum flip-flops per
instance). Results (Yosys 0.69):
   dsp_counter, full packing          FAIL: 0 of 10 flip-flops; 11 outputs became constant
   dsp_counter, multonly              PASS
   surf_video pre-fix, full packing   FAIL: (top) 627 -> 236 FFs, u_cfg_cdc 220 -> 0, 32 Kbit ROM
                                      with no block RAM, 27 outputs became constant
   surf_video pre-fix, multonly       PASS (852 of 852)
   surf_video fixed, full packing     PASS (862 of 863)
   flow_features, full packing        PASS (445 FFs + 94 held in DSPs of 474)
   flow_demo, flow_features (safe)    PASS
   make test-flow repeats the dsp_counter cases with the main image's Yosys 0.52 (full FAIL as
   expected; safe and -nodsp PASS), so a future Yosys that fixes the pass shows up there.

Not demonstrated: that no other DSP pattern is affected (the check is the safeguard), or the
upstream status (no matching issue found by a search of YosysHQ/yosys issues for
"xilinx_dsp preadder"; nothing was filed from here).
