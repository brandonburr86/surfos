soc track: issues found by the tests and fixed (2026-10-15)

* sysinfo DDR_STATUS.TIMEOUT: the sticky bit appeared one cycle after the bridge's pulse, so a
  load right behind the abandoned DDR access (back to back, the pulse comes with the error
  response) read 0. Found by soc_periph.sbs on tb_soc; now the read value is (sticky | pulse).
* surf_textram: Yosys mapped it to 4096 LUTs of distributed RAM, because it refuses READ_FIRST
  on a 7-series true dual-port block RAM with different port clocks (UG473's read-first
  collision erratum). Found by synth-soc; port A now reads only when it does not write
  (NO_CHANGE), which maps to 4 RAMB36 and can never corrupt memory on a collision.
* tb_uart did not check TX_IE while the shifter is busy and the FIFO empty (a mutant survived);
  tb_interconnect's calibration-lost case could start while the DDR slave was still ready from
  its random state (a mutant survived on one run). Both tests were tightened.
* The build identity compiled into surfsim and into the scripts that check sysinfo got out of
  step between commits; they now share a stamp.
* Icarus: two processes calling the same static task in one time step can overwrite each
  other's arguments (the task body runs as a scheduled child thread). Hit in the RAMB36E1
  simulation model, whose task is now automatic; the RTL has no tasks and every testbench task
  has a single caller.

soc round 2: the whole system in surfsim (2026-10-16)

* Nothing in the RTL had to change: SurfBoot and the Arty kernel ran on the first try with the
  io models wired in (test-soc-system-boot.txt). No SD, PS/2 or SurfBus protocol violation was
  seen by the models in any run.
* The kernel runs from DDR, fetched one word at a time (the core keeps one fetch outstanding and
  has no cache; the DDR model answers in 2 to 12 cycles, ready 70 %): 24.3 million DDR fetches in
  the 260 million cycles after the handoff, idle time included. Simulated times are therefore
  long, as in the fw track's emulator: the boot to the prompt is 5.1 s,
  crc32 of the 353 KiB package 23 s (584 million cycles, measured on the first run of the test,
  before it was replaced by an 8 KiB file), the self test 64 s (it passes on the RTL:
  test-soc-system-selftest.txt).
* The screen during `tasks` shows partly written and blank rows where the UART has whole lines
  (two kernel tasks printing at once); the fw emulator's text screen shows the same kind of
  damage at that point, so it is the kernel's console and not the RTL. Reported for the os track.
* pix_clk and the VGA capture cost about 1 % of the run time, so the pixel domain always runs.
