SurfCPU release: the QSPI flash images, the configuration options, programming with the fake programmer
2026-10-16, release track, on the release 1.0.0-pre-bb066932 (commit bb066932, release.txt in this
directory); docs/RELEASE.md sections 6 and 7. Nothing was written to a real flash: tools/program.sh
ran with OPENFPGALOADER set to the board tests' fake (sim/board/tools/fake/openFPGALoader), which logs
its calls and programs nothing; no board was connected.

Sources for the facts below (read 2026-10-16):
  AMD UG470 v1.17 (2023-12-05), 7 Series FPGAs Configuration: figure 2-13 note 2 ("The CCLK frequency
    starts at 3 MHz typical ... increases if the ConfigRate option is utilized"); table 5-25 (command
    codes, BSPI_READ 10010, IPROG 01111); table 5-27 (CTL0 bit 10 ConfigFallback, 1 = disabled);
    chapter 7 (MultiBoot: fallback on an IDCODE error, a CRC error or a watchdog time-out; embedded
    IPROG ignored during fallback; "for SPI configuration mode, fallback loading of the golden images
    always uses the x1 configuration mode").
  AMD UG470 v1.10 (2015-06-24): table 1-1 (standard bitstream lengths: 7A35T 17,536,096 bits, 7A100T
    30,606,304); table 5-19 (a Vivado bitstream: the TIMER, WBSTAR and NULL-command placeholders for
    MultiBoot, the CRC checks); table 5-41 (BSPI: SPI_buswidth [9:8], SPI_read_opcode [7:0]); tables
    5-30/5-31 (COR0, OSCFSEL [22:17] "Select CCLK frequency in Master modes (2 MHz - 60 MHz)").
  Digilent Arty A7 reference manual (the board track's cached copy): section 4 (JP1 MODE selects
    configuration from the Quad-SPI flash at power-up; "Not setting the mode jumper is useful to
    prevent the FPGA from being configured from Quad-SPI Flash until a JTAG programming occurs";
    JTAG works whatever JP1 is), 4.2 ("x1, x2, and x4 bus widths and data rates of up to 50 MHz";
    "less than a second" with the Xilinx tools' settings), 5.2 (128 Mbit, N25Q128A13ESF40).
  openFPGALoader master, src/xilinx.cpp: reverse = true only for MEM_MODE (JTAG load) and XCF PROMs,
    so a .bit written to an SPI flash is its data after the header, bits as they are; a .bin goes
    through RawParser the same way; the flash is reached through the spiOverJtag bridge bitstream
    loaded over JTAG. src/bitparser.cpp: the data after field e, its length from field e.
    src/spiFlash.cpp: "JEDEC ID: 0x..." and "Detected: <maker> <model> ..." for a known part;
    64 KiB block erases (4 KiB where the part has them); a protected range is refused unless
    --unprotect-flash; --verify reads back and compares.
  The pinned image surfcpu-openxc7:2026-10-15: xc7frames2bit --helpfull lists only --architecture,
    --frm_file, --output_file, --part_file and --part_name: no configuration options.
